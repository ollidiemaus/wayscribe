# 6.11–6.21 Launch trackers (1.0)

Part of the [Wayscribe architecture](../ARCHITECTURE.md); other sections are listed there.

The trackers for Forever's launch on 2026-11-04 (the plan and its dates are in §11). The beta
ends on 2026-10-21, before there is time to check them in game, so these sections are the spec they
are built to. Each section is rewritten with what was actually built. The APIs named here are in
Forever's UI source (build 70374) and are read by `/ws probe` (§12 row 16). Terms such as
*probed*, *first visit* and *notable gear* are defined in [GLOSSARY.md](../../GLOSSARY.md).

## 6.11 Rules for the launch trackers
- **Ready to ship = probed + unit-tested + fails silent.** If an event never fires or an API returns
  nothing, the tracker writes nothing and raises no error. The in-game checks for these trackers
  are under *After launch* in [ingame-tests.md](../ingame-tests.md).
- **Snapshots first.** A tracker reads the current state (money, standings, worn items, known flight
  paths) and compares it with its saved snapshot. Events only say when to look, so a missed event
  is caught at the next look. A chat line is parsed only when Forever's UI source defines its
  global string, and never as the only signal.
- **The first look is silent.** What a tracker sees the first time it runs happened before it
  existed. The exceptions are listed per tracker.
- **Changes found at login are recorded** on the login day, as Professions does (§6.3). Gold and Home
  are the exceptions: they take the new value silently.
- **A restored journal never repeats a first.** A tracker's snapshot is its Store state (§4.4),
  which the backup carries with the entries. A journal that comes back without it makes the next
  look a first look again, and the firsts (§4.5), which are rebuilt from the entries, keep a first
  from being marked twice. Each section says what else a tracker reads back from its entries.
- **Entries for rare moments, counters for frequent ones.** Only Gold is a counter.
- **No new journal tabs or filter categories.** *Travel*: first visits, flight paths, home.
  *Progress*: reputation, notable gear, Legacy Challenges, collections, gold. *Adventure*: guild.
  *PvP*: rank.
- **On by default.** In developer mode, the launch trace keeps what each new tracker saw, so a wrong
  entry at launch comes with evidence.
- **Every look is traced** (`Data/Trace.lua`). In developer mode each look adds one line through
  `ns.Trace:Add(tracker, event, outcome, name, value, ...)`: the time, the tracker, the event that
  asked for the look (a debounced burst names each event, joined by `+`: `AskForLook` and `TakeAsked`,
  which every tracker gets from `Core/Trackers.lua`), the values it read and how
  the look ended, the looks that write nothing included. A nil value reads `missing`, a secret one
  `secret`, a table its keys. Values read through `Compat.Call` arrive with secrets already nil, so a
  tracker that needs to tell them apart passes the raw value. The lines are kept account-wide in
  `WayscribeDB.trace`, the newest 500. `/ws trace` prints the last 20 and `/ws trace clear` starts
  over. Without developer mode nothing is kept. The trace never raises: a value it can't describe
  reads `trace error`, so it can't count against the tracker (§3.4). The duel trace (`/ws duellog`,
  §12 row 15) is separate.

## 6.12 First visits
Built (`Trackers/FirstVisits.lua`, record `FIRST_VISIT { map }`, category *travel*).
- `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA` and `PLAYER_CONTROL_GAINED` (a taxi landed) each
  ask for a look one second later, so a burst of them is one look and the best map has caught up
  with a loading screen.
- A look takes the best map's zone: `Compat.GetZoneOf` walks up `C_Map.GetMapInfo` to the first map
  of type 3. In Forever's `UiMap` (build 70374) the cities are type 3 maps directly under their
  continent, so Thunder Bluff is not Mulgore, and Zephras Isle is a zone under Azeroth. A cave's
  map counts as its zone.
- No look on a taxi or in an instance (any `instanceType` but `"none"`, or none known): the
  Dungeons tracker covers instances (§6.6), and the landing's `PLAYER_CONTROL_GAINED` looks again.
- One entry per zone, ever: the firsts key `VISIT:<map>` (§4.5) says the zone was recorded.
- **The first look is silent** for the zone the character stands in and for every zone its world
  map shows explored (`C_MapExplorationInfo.GetExploredMapTextures`, through
  `Compat.GetExploredZones`). A zone counts when it returns any texture, also one the map shows
  only under the mouse (`isShownByMouseOver`). Those are kept in `state.visits`, which the backup
  carries. A zone without areas to uncover (likely the cities) can't be known that way, so an older
  character may get a late "first time" for one.
- **A level 1 character's first look takes nothing:** the zone it stands in is recorded, so its
  starting zone is the journal's first entry, and its explored zones are left out. On the beta the
  map showed Alterac Mountains, Elwynn Forest and Moonglade explored on a brand-new level 1
  character as on a level 3 one, none of them visited; why is unknown (§12 row 16). Above level 1
  they are still taken, so an older character never gets a first visit for those three.
- Without the APIs nothing is written: no zone, no look; no explored maps, only the first zone is
  known.
- Year: a line on the Footsteps card, "12 zones visited for the first time".
- Trace (§6.11): the look when the tracker is switched on names `enable`. Each look reads `taxi`,
  `instance`, `map` and `zone`, and the first look also `level` and `explored` (on a level 1
  character only for the trace: they aren't taken). It ends `recorded`,
  `first look` (silent), `known` (in `state.visits`), `recorded before` (in the firsts), `on a taxi`,
  `in an instance`, `no zone`, `read-only` or `not written: <reason>`.
- `/ws probe`: `firstVisit.zone` (the zone the tracker takes), `firstVisit.map.<n>` (the chain of
  maps) and `firstVisit.explored`: each zone that returns textures, with how many and how many of
  them are hover-only (`1412 4/0, 1416 2/2 (textures/hover-only)`, `none` without any).

## 6.13 Gold
Built (`Trackers/Gold.lua`, counter `gold { earned, spent }` in copper, category *progress*).
- On `PLAYER_MONEY`, `GetMoney()` (through `Compat.GetMoney`) is compared with the saved amount
  (`state.gold.money`). Increases count as *earned* and decreases as *spent*. Every source counts:
  loot, quests, vendors, repairs, trades, mail and the auction house. Without chat parsing the
  sources can't be told apart, so gold mailed to one's own alt counts as spent here and earned
  there. A missed event is caught at the next one, which counts the whole difference.
- The look when the tracker is switched on (every login and `/reload`, and switching it on in the
  settings) takes the amount silently, so money that changed while Wayscribe wasn't watching never
  lands on the wrong day. So do the first look ever and the first `PLAYER_ENTERING_WORLD` after
  switching on, in case the money wasn't known yet at `PLAYER_LOGIN` (a 0 there would make the whole
  balance "earned").
- Day page: one line, "Gold: 3g 20s earned, 1g 5s spent", or only the half that happened. The
  game's coin format without the coin icons, as `GetMoneyString` writes it in colorblind mode: the
  client's `GOLD_AMOUNT_SYMBOL`, `SILVER_` and `COPPER_` (the locale's g/s/c, G/S/K as fallback),
  zero denominations left out, thousands separated.
- Year card (order 95, before *Time played*): earned as the big number (spent, for a year of only
  spending), then spent, the best day
  (the most earned) and the most held at once. The best day comes from the counters: a counter's
  `rollup` hook keeps the month's `goldBest = { earned, day }` and its `merge` takes the year's,
  so a rebuild restores it. **The most held at once** is not in the counters (a day holding only a
  peak would show as a day with nothing on it), so it is kept per year in the tracker's state,
  `state.gold.most[year]`, the highest amount any look read that year, silent ones included. The
  backup carries it; a journal rebuilt or restored without the state loses it until the next look.
- Without `GetMoney`, or when it errors or returns a secret, the look writes nothing and logs
  nothing; the first readable amount is then the first look.
- Trace (§6.11): each look names `enable`, `PLAYER_ENTERING_WORLD` or `PLAYER_MONEY`, reads `money` (raw, so a secret reads
  `secret`) and `saved`, and ends `first look`, `taken` (silent), `earned`, `spent`, `unchanged`,
  `no money` or `read-only`.

## 6.14 Reputation
Built (`Trackers/Reputation.lua`, record `REPUTATION { faction, standing, name? }`, category
*progress*).
- `UPDATE_FACTION`, `PLAYER_ENTERING_WORLD` and switching the tracker on each ask for a look one
  second later, so a burst of updates is one look. A look reads every standing through `C_Reputation`
  (`Compat.GetFactionStandings`): `GetNumFactions` and `GetFactionDataByIndex` for the list, where a
  header counts only with `isHeaderWithRep`, then `GetFactionDataByID` (`Compat.GetFactionStanding`)
  for each known faction the list didn't show, since a collapsed header hides its factions. Each
  faction has a `reaction` from 1 (Hated) to 8 (Exalted); a secret or odd value skips that faction.
- The look compares them with `state.reputation = { [factionID] = { r, hi, lo } }`: the reaction last
  read and the highest and lowest ever read. An entry for each standing passed above the highest, from
  Friendly up, and below the lowest, from Hostile down, so a missed event writes every standing it
  passed (Neutral to Revered is three entries). Falling back and climbing again repeats nothing, and
  neither does climbing back to a standing the faction held at the first look.
- A faction met for the first time is only taken into the snapshot: meeting it is no entry.
- **An unchanged look saves nothing.** The look first compares what it read with the saved snapshot
  in place; when every faction read is there with the same reaction it ends `unchanged` without
  copying or saving the snapshot, so a kill that gives reputation without a new standing costs
  almost nothing. Only a changed reaction or a new faction copies the snapshot, writes the entries and
  saves it, and a failed write leaves the saved snapshot as it was.
- One entry per faction and standing, ever: the firsts key `REP:<faction>:<standing>` (§4.5). A journal
  restored without the tracker's state takes the standings silently again and still never repeats one.
- **The first look is silent.** A change found at login, or when the tracker is switched back on, is
  recorded on that day (§6.11).
- Factions 2800 (PvP Rank Points) and 2802 (Legacy Track) are progress tracks, not standings, and are
  left out (`C_Reputation` doesn't know them by ID on the beta anyway).
- The faction's name is captured when the entry is written ("Faction 81" if it had none). The
  standing's name is read at display time: the client's `FACTION_STANDING_LABEL<n>`, or `_FEMALE` for a
  female character (`UnitSex` 3; German has both), with the locale's own names as fallback.
  "Reached Honored with Thunder Bluff", "Fell to Hostile with Booty Bay".
- Without `C_Reputation`, or when it errors or returns secrets, the look writes nothing and logs
  nothing; a look that reads no faction isn't a first look either.
- Year card (order 85, after *Quests*): the standings reached as the big number, then the factions
  whose best that year is Exalted, Revered and Honored (a line each, with the client's label), and the
  faction that climbed the most standings (by name on a tie). It comes from the entries: the record's
  rollup keeps per faction the best standing, the standings climbed and the entries.
- Trace (§6.11): each look names `enable`, `UPDATE_FACTION` or `PLAYER_ENTERING_WORLD` (joined with `+`
  in a burst), reads `rows` (raw `GetNumFactions`), `factions` (how many standings were read) and, when
  any reaction changed, `changed` (`81:5>6`). It ends `first look` (silent), `recorded <n>`, `known` (a
  change with no new standing), `unchanged`, `no factions`, `read-only` or `not written: <reason>`.

## 6.15 Notable gear
Built (`Trackers/Gear.lua`, record `GEAR { item, quality, name?, notFirst? }`, category *progress*).
- On `PLAYER_EQUIPMENT_CHANGED(slot)`, that slot's item and quality are read
  (`Compat.GetEquippedItem`: `GetInventoryItemID` and `GetInventoryItemQuality`). Slots 1 to 19 are
  gear; the bag slots after them are ignored.
- Switching the tracker on (every login and /reload) and `PLAYER_ENTERING_WORLD` ask for a look at
  every slot one second later, so a missed event is caught there, and a change made while Wayscribe
  was off is recorded on the login day.
- The tracker keeps every item it has seen worn, `state.gear = { items = { [itemID] = true },
  hadRare, hadEpic }`, whatever its quality. An item seen before repeats nothing: re-equipping it, a second copy in the
  other ring or trinket slot.
- An equipment change for an item seen before ends at once (`known`): it reads the saved snapshot
  without copying or saving it, so a set swap costs the same for a character who has worn a thousand
  items as for one at level 5. A new item goes into the saved snapshot directly, a notable one only
  once its entry is written, so a failed write changes nothing; a read-only journal's snapshot isn't
  touched. A look at every slot, once per burst, works on a copy.
- An entry for the first rare item (quality 3), marked as a *first* (firsts key `GEAR:RARE`); later
  rare items make none. An entry for every epic or better item (4 to 6), once per item; the first is
  marked as a *first* (`GEAR:EPIC`). Heirlooms (7) are left out. Below rare is no entry.
- **The first look is silent:** what is worn already is taken as seen. A rare or an epic among it
  was the character's first, so the journal marks none later: `hadRare` makes a later rare no entry,
  and `hadEpic` writes later epics with `notFirst`, which keeps them out of the firsts, also when
  they are rebuilt. A look that reads no item (no API, or the inventory not loaded yet) isn't a first
  look.
- An item whose quality the client hasn't loaded yet isn't taken: the event asks for a look at every
  slot a second later, and every later look reads it again.
- A journal restored without the tracker's state takes what is worn silently again; its epics and
  `GEAR:RARE` come from the journal, so nothing repeats, and an epic among its entries was had.
- The item's name is captured when the entry is written, else read at display time ("item 3000" if
  neither has it). "Equipped your first rare item: Thrash Blade", "Equipped your first epic item:
  Hand of Justice", "Equipped an epic item: Ironfoe", "Equipped a legendary item: Thunderfury".
- Without the inventory API, or when it errors or returns a secret, nothing is written or logged.
- Year card (order 35, after *Bosses*): the epics worn that year as the big number (none when there
  were none), then the first rare and the first epic with their dates, when they fell in that year.
  It comes from the entries: the record's rollup counts the epics and keeps the two firsts.
- Trace (§6.11): an equipment change names `PLAYER_EQUIPMENT_CHANGED` and reads `slot`, `item` and
  `quality` (raw); it ends `first rare`, `first epic`, `epic`, `later rare`, `known`, `not notable`,
  `no quality`, `empty`, `unreadable`, `read-only` or `not written: <reason>`. A look at every slot
  names `enable`, `PLAYER_ENTERING_WORLD` or `PLAYER_EQUIPMENT_CHANGED` (before the first look; joined
  with `+`), reads `worn` and, for items not seen before, `new` (`2000:3`, `?` for a quality not
  loaded), and ends `first look`, `recorded <n>`, `nothing notable`, `unchanged`, `no items`,
  `read-only` or `not written: <reason>`.

## 6.16 Legacy Challenges
Built (`Trackers/LegacyChallenges.lua`, record `LEGACY_CHALLENGE { challenge, name? }`, category
*progress*).
- Forever turns the achievement frame into Legacy Challenges, and the game API is the achievement
  one. A look reads every challenge (`Compat.GetLegacyChallenges`: `GetCategoryList`,
  `GetCategoryNumAchievements`, then `GetAchievementInfo(category, index)`) with its *completed*, its
  date (the year counts from 2000), its flags and *wasEarnedByMe*. Switching the tracker on (every
  login and /reload), `PLAYER_ENTERING_WORLD` and `ACHIEVEMENT_EARNED(id)` ask for a look one second
  later, so a missed event is caught at the next look.
- The tracker keeps every challenge it has seen completed, `state.legacy = { done = { [id] = true } }`.
  One entry per challenge, ever: the firsts key `LEGACY:<id>`, which the backup carries.
- **Whose challenge it is.** *wasEarnedByMe* doesn't tell: on the beta a brand-new character read
  "Played in the WoW: Forever Beta" completed and earned by it six days before it was created
  (§12 row 16). That challenge has the account-wide flag (`ACHIEVEMENT_FLAGS_ACCOUNT`, `0x20000`), as
  do 147 of Forever's 436 (build 70374), the class and profession ranks among them. So, decided on
  2026-10-15:
  - a challenge named by `ACHIEVEMENT_EARNED` is this character's and makes an entry, account-wide
    or not (`alreadyEarned` is ignored). The event's ID is kept until a look can read the
    challenges, and its name is read by ID when its row can't be. When every row could be read and
    the ID isn't among them, it isn't a challenge (a guild achievement, say) and makes none;
  - at a look, a newly completed account-wide challenge, or one whose *wasEarnedByMe* is false, is
    taken silently: another character of the account may have earned it. The others make an entry,
    on the day of the look (a change found at login is recorded on the login day);
  - the price: an account-wide challenge this character earned while Wayscribe was off or missing
    the event makes no entry.
- **The first look back-fills** the completed challenges that count as this character's, on the
  game's date: dated at the end of that day (never later than now), flagged as back-filled
  (`record.bf`) and shown without a time, like back-filled quest chains (§6.7). A challenge without a
  readable date is back-filled now. A level 1 character's first look takes everything silently,
  since what it reads as completed came with the account (§6.12 does the same with explored zones).
  A look that reads no challenge isn't a first look. A journal restored without the tracker's state
  back-fills again, and its firsts keep anything from repeating.
- Levels on the Legacy Track (faction 2802) make no entry, and Reputation leaves 2802 out (§6.14).
- The challenge's name is captured when the entry is written ("challenge 64283" without one).
  "Completed a Legacy Challenge: Into the Barrens".
- Without the achievement API, or when it errors or returns a secret, nothing is written or logged;
  a challenge row that can't be read is left out.
- Year card (order 87, after *Reputation*): how many challenges were completed that year as the big
  number, and the latest with its date. It comes from the entries' rollup.
- Trace (§6.11): names `enable`, `PLAYER_ENTERING_WORLD` or `ACHIEVEMENT_EARNED` (joined with `+`),
  reads `challenges` (the count, or the raw category list when it can't be read), `completed`,
  `earned` (the IDs from `ACHIEVEMENT_EARNED`) and `new` (completed since the last look,
  `:account` or `:other` after one taken silently), and ends `back-filled <n>`, `first look`,
  `recorded <n>`, `not this character's`, `unchanged`, `no challenges`, `read-only` or
  `not written: <reason>`.

## 6.17 Flight paths
Built (`Trackers/FlightPaths.lua`, record `FLIGHT_PATH { node?, name? }`, category *travel*).
- The known nodes can only be read while a taxi map is open, so `TAXIMAP_OPENED` asks for a look
  0.2 seconds later. The chat line "New flight path discovered!" (`ERR_NEWTAXIPATH`, matched as a
  whole) only asks for another look; with no taxi map open it writes nothing.
- `Compat.GetTaxiNodes` reads Forever's flight map first: `GetTaxiMapID()` (a positive ID; away
  from a flight master it gives `-1` or nil), then `C_TaxiMap.GetAllTaxiNodes(mapID)`, where state 0
  (current) and 1 (reachable) mean known. When that reads no nodes it reads the old taxi frame:
  `NumTaxiNodes`, `TaxiNodeGetType` (`CURRENT` or `REACHABLE`) and `TaxiNodeName`. At the Thunder
  Bluff flight master both read 22 nodes. A node that can't be read is left out.
- A node is its `nodeID` on the flight map and its name on the old frame, which has no IDs. One
  entry per node, ever: the firsts key `FLIGHT:<nodeID>` (or `FLIGHT:name:<name>`) says it was
  recorded, so a relog or a restored journal repeats nothing. Names are in the client's language, so
  on the old frame a language switch would repeat its nodes; the flight map always read too on the
  beta, so the frame is only a fallback. The entry keeps the node's name
  ("New flight path: Thunder Bluff, Mulgore").
- A look compares the known nodes with `state.flightPaths = { seen = { [continent] = true },
  known = { [node] = true } }`, so a path learned without a look is recorded at the next flight
  master. The continent is `map:<taxi map ID>` on the flight map and `frame:<continent map>` (the
  player's, `Compat.GetContinentOf`) on the old frame, so each source has its own first look.
- **The first map on each continent is silent**, except when the only known node is the one the
  player stands at: then it was just learned, which keeps a fresh character's first flight path. A
  look that reads no known node is no first look.
- Year: a line on the Footsteps card, "4 flight paths learned" (the `FLIGHT_PATH` entries).
- Trace (§6.11): each look names `TAXIMAP_OPENED` and `CHAT_MSG_SYSTEM`, and reads `source` (`map`
  or `frame`), `map` (the taxi map ID, or the player's continent for the frame), `nodes` (all the
  map shows), `known`, `current` (the node's ID, or its name on the frame) and `new`. It ends
  `recorded <n>`, `first look` (silent), `unchanged`, `no taxi map`, `no known nodes`, `read-only`
  or `not written: <reason>`.
- `/ws probe`: `flightPaths.oldFrame`, `flightPaths.taxiMap` and `flightPaths.nodes` (by state).

## 6.18 Guild
Built (`Trackers/Guild.lua`, record `GUILD { joined, name }`, category *adventure*).
- `PLAYER_GUILD_UPDATE` (for the player, or with no unit) and the login (`PLAYER_ENTERING_WORLD`,
  and the tracker's enable) ask for a look a second later; a burst is one look.
  `Compat.GetGuild` reads `IsInGuild()` (a boolean; anything else is unreadable) and, in a guild,
  the first value of `GetGuildInfo("player")`. The beta's probe read `false` and nil.
- A look compares the guild with `state.guild = { name = <guild's name> or false }`, so a guild left
  or joined while Wayscribe was off is found at the next look, at login on the login day. A switch
  from one guild to another writes both entries: "Left the guild <Red Hand>", then "Joined the
  guild <Bloodfang>". The entries keep the guild's name from when they were written.
- **Only `IsInGuild() == false` means the character left.** In a guild with the name still missing
  (right after login) the look changes nothing and looks again 5 seconds later, at most three
  times in a row; the next `PLAYER_GUILD_UPDATE` looks too.
- Rank changes leave the name as it was, so they make no entry. Guilds are joined and left more than
  once, so there are no firsts; the snapshot alone says what was recorded. A journal that comes back
  without it (or a brand-new one) makes the next look a silent first look, so nothing repeats.
- **The first look is silent:** the guild the character is already in makes no entry. A look that
  can't read the guild is no first look. No year card.
- Trace (§6.11): each look names its events (`enable`, `PLAYER_ENTERING_WORLD`,
  `PLAYER_GUILD_UPDATE`, `retry`) and reads `inGuild` and, in a guild, `name` (raw, so a secret
  reads `secret`). It ends `first look`, `unchanged`, `left`, `joined`, `left + joined`,
  `name missing`, `unreadable`, `read-only` or `not written: <reason>`.
- `/ws probe`: `guild.inGuild` and `guild.name`.

## 6.19 Home
Built (`Trackers/Home.lua`, record `HOME { name }`, category *travel*).
- `HEARTHSTONE_BOUND` (which no Blizzard UI listens to), `CONFIRM_BINDER`, `PLAYER_ENTERING_WORLD`
  (the login, and every zoning after it) and the tracker's enable ask for a look a second later; a
  burst is one look. `Compat.GetBindLocation` reads `GetBindLocation()`, the inn's place in the
  client's language; an empty or secret name is unreadable. The beta's probe read "Camp Narache",
  "Bloodhoof Village", "Thunder Bluff" and "Camp Taurajo".
- A look compares the place with `state.home = { name = <place> }`. A new place during play writes
  "Hearthstone bound to Thunder Bluff"; the entry keeps the place as it was read.
- **The first look of each session takes the home silently**: the login (and a `/reload`) reads the
  place in the client's language, so a switched language is no move, and neither is a bind made
  while Wayscribe was off. The session's first readable look is that look; a look that can't read
  the place, or can't write, leaves it for the next one. Switching the tracker off and on during
  play keeps the session's look, so a bind made while it was off is found at its next look.
- A missed `HEARTHSTONE_BOUND` is caught at the next look during play (`CONFIRM_BINDER` at the next
  innkeeper, or a zoning). There are no firsts; the snapshot alone says what was recorded, and a
  journal that comes back without it makes the next look a silent first look. No year card.
- Trace (§6.11): each look names its events (`enable`, `PLAYER_ENTERING_WORLD`, `CONFIRM_BINDER`,
  `HEARTHSTONE_BOUND`) and reads `bind` (raw, so a secret reads `secret`). It ends `first look`,
  `taken at login`, `unchanged`, `moved`, `unreadable`, `read-only` or `not written: <reason>`.
- `/ws probe`: `home.bind`.

## 6.20 Collections
Built for mounts (`Trackers/Collections.lua`, record `MOUNT { mount, name?, notFirst? }`, category
*progress*).
- Forever has Retail's Collections window. `NEW_MOUNT_ADDED`, `COMPANION_LEARNED`, the login
  (`PLAYER_ENTERING_WORLD`, every zoning after it) and the tracker's enable ask for a look a second
  later; a burst is one look. `Compat.GetMounts` reads `C_MountJournal.GetMountIDs` and, for each
  ID, `GetMountInfoByID` (its 11th value, *isCollected*). A mount whose row can't be read, or whose
  flag isn't a boolean yet, is left out: a look before the flags load can't make owned mounts new. The beta's probe read 136 mounts in the journal and none collected.
- A look compares the collected mounts with `state.collections = { mounts = { [mountID] = true },
  hadMount }`,
  so a mount collected without an event (or while Wayscribe was off) is found at the next look, at
  login on the login day. Each new one writes "New mount: Brown Horse", with the name read when it
  is written ("mount 6" without one).
- **The first mount is the firsts key `MOUNT`**, so only it is marked as a first; the snapshot alone
  says which mounts were recorded. A journal that comes back without it (a backup restored without
  the state, or a brand-new one) makes the next look a silent first look, and the firsts key keeps
  a later mount from being marked again.
- **The first look is silent:** the mounts owned already make no entry, and a character that owned
  one had its first: `hadMount` writes later mounts with `notFirst`, which keeps them out of the
  firsts, also when they are rebuilt. A look that reads no mount (no API, an error, a secret, or an
  empty journal) is no first look.
- The price: if Forever's mounts are account-wide as Retail's are, a mount another character
  collects is recorded at this character's next login. The in-game checks ask for it.
- **Mounts only at launch.** Pets (`C_PetJournal`, `NEW_PET_ADDED`) and toys (`C_ToyBox`,
  `NEW_TOY_ADDED`) wait until after launch. The beta read `0 of 0` for both on characters that own
  none, and the journals list only what is owned (`onlyShowCollectedItemsInJournal`), so it couldn't
  tell "doesn't work" from "nothing to show". No pet or toy was learned on the beta. Their
  events register and pet items teach through the journal's spell (55884), so a learned pet in
  `/ws probe` after launch decides whether they join this tracker.
- Year card (order 88, after *Legacy Challenges*): how many mounts were collected that year as the
  big number, and the first mount with its date when it came that year. It comes from the rollup.
- Trace (§6.11): each look names its events (`enable`, `PLAYER_ENTERING_WORLD`, `NEW_MOUNT_ADDED`,
  `COMPANION_LEARNED`) and reads `mounts` (the journal's count, or the raw ID list when it can't be
  read), `collected` and `new` (the new mounts' IDs). It ends `first look`, `recorded <n>`,
  `unchanged`, `no mounts`, `read-only` or `not written: <reason>`.
- `/ws probe`: `collections.mounts`, `collections.pets` and `collections.toys`.

## 6.21 PvP rank (stretch)
Built (`Trackers/PvPRank.lua`, record `PVP_RANK { rank, season, title? }`, category *pvp*).
- Forever's honor ranks are a seasonal renown track on the PvP rank faction (2800).
  `PLAYER_PVP_RANK_CHANGED`, `MAJOR_FACTION_RENOWN_LEVEL_CHANGED` (for faction 2800, or without a
  readable faction; the Legacy Track's 2802 is ignored), the login (`PLAYER_ENTERING_WORLD`, every
  zoning after it) and the tracker's enable ask for a look a second later; a burst is one look.
  `Compat.GetPvPRank` reads `C_MajorFactions.GetMajorFactionProgressionInfo(2800).renownLevel` and
  `GetCurrentArenaSeason()`; a look that can't read both as numbers is unreadable. The beta's probe
  read rank 0 in season 0.
- A look compares the rank with `state.pvpRank = { season = <season>, best = <highest rank> }`. A
  rank above the season's best writes "Reached PvP rank 3: Sergeant", so a missed event is caught at
  the next look, at login on the login day. Ranks skipped between two looks make one entry, for the
  rank reached.
- The title is read when the entry is written, by `Compat.GetPvPRankTitle`, the way Blizzard's
  `PVPRankFrame` builds it: the client's `PVP_RANK_<Rank_1 + rank - 1>_<0 Horde, 1 Alliance>`
  (`Enum.PvPRanks.Rank_1` is 5), its `_FEMALE` form for a female character. Without one the entry
  reads "Reached PvP rank 6".
- **Losing a rank, climbing back to the best, and a new season make no entry.** A look that finds
  another season takes its rank silently as the season's best, so a rank reached in a new season
  before the first look of that season is no entry; from then on each new highest rank is.
- **The first look is silent.** There are no firsts; the snapshot alone says what was recorded, and
  a journal that comes back without it (a backup restored without the state, or a brand-new one)
  makes the next look a silent first look.
- Year card (order 56, after *Duels*): the highest rank reached that year as the big number, its
  title as the caption, and when and in which season it was reached. It comes from the rollup.
- Trace (§6.11): each look names its events (`enable`, `PLAYER_ENTERING_WORLD`,
  `PLAYER_PVP_RANK_CHANGED`, `MAJOR_FACTION_RENOWN_LEVEL_CHANGED`) and reads `rank` and `season`
  (raw, so a secret reads `secret`). It ends `first look`, `recorded <rank>`, `unchanged`,
  `new season`, `unreadable`, `read-only` or `not written: <reason>`.
- `/ws probe`: `pvpRank.level` and `pvpRank.season`.
